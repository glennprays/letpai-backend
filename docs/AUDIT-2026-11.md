# Letpai Backend Codebase Audit — 2026-11-08

- **Commit audited:** `babc8a4` + 37 staged files (+523/−12) — the working tree was audited as-is.
- **Method:** code-review skill, three axes — Standards, Spec, Security — each run by an independent read-only agent against the working tree. Every finding cites `path:line`. **Hard violation** = breach of a documented standard/spec. **Judgement call** = smell/heuristic, always advisory. Findings are reported, not fixed.
- **Spec-axis note:** no issue tracker exists (`docs/agents/issue-tracker.md` missing) → spec sources are repo docs: `docs/swagger.yaml`, `README.md`, `ADMIN_TODO.md`.

## Standards

Reviewed against `AGENTS.md` (hexagonal dependency rules, error-handling taxonomy via `domain.Err*` + `httperror.FromError`, use-case/repository patterns, Fiber JSON response shape, migrations-only schema changes) plus the 12-smell Fowler baseline (all smells are judgement calls; a documented repo standard overrides).

### Hard violations

- **`internal/httperror/httperror.go:49–50`** (AGENTS.md "HTTP Error Conversion") — the fallback branch returns `err.Error()` verbatim to clients with status 500, leaking internal error text (e.g. SQL driver messages). The convention maps through domain sentinels; unknown errors should yield a fixed message.
- **`internal/httperror/httperror.go:35–48`** — `ErrInvalidStatusTransition` and `ErrInvalidPaymentStatusTransition` (`domain/errors.go:13–14`) have no switch case, so payment rule rejections (`usecase/payment/submit_payment.go:84`, `approve_payment.go:66`, `reject_payment.go:82`) surface as 500 instead of 4xx. `entity/session.go:11` and `entity/session_participant.go:11` also define near-duplicate sentinels (`ErrInvalidStatusTransitionError`) mapped nowhere — duplicated/mysterious names.
- **`internal/handler/dashboard_handler.go:26–30`** — bypasses `httperror.FromError` and returns `{"error": err.Error()}` without the success envelope, leaking internal error text; every other handler uses `apiErr.Response()`. Breaches "HTTP Error Conversion" + "Fiber JSON Response".
- **`internal/handler/payment_handler.go:202–205`** — public unauthenticated route returns raw `err.Error()` with hardcoded 500; a `domain.ErrNotFound` (participant not found) becomes 500 with internal text on an anonymous-reachable surface.
- **BUG** — `internal/usecase/dashboard/get_dashboard.go:57–61`: `CountBySessionIDAndStatus` filters `WHERE session_id = $1` (`repository/participant_postgres.go:378–380`), but the dashboard passes `userID` — `pendingCount` is wrong for every user. Needs a user-scoped count.
- **`internal/repository/otp_postgres.go:26–172`** — migration 000017 drops `otp_verifications`/`admin_otp_verifications` ("no longer read or written by the live code path"), yet this repository still queries both tables and `wire.go:40` still injects it into register/verify-otp/admin OTP usecases (`wire_gen.go:50–64`) — runtime SQL failures or a dead parallel path. Breaches migrations-only schema consistency + Speculative Generality. Delete the Postgres OTP stack, the unused `AdminOTPVerificationRepository` (`wire.go:49`), and its entity/ports.

### Judgement calls

- **`internal/usecase/session/get_session_detail.go:88–91`** — on count error the usecase sets `paidCount = 0` and returns misreported session detail, violating the error-flow convention (should wrap in `domain.NewError`).
- **`internal/repository/session_postgres.go:100–175`** (Duplicated Code) — `FindAll` in `contact_postgres.go:184–269` and `session_postgres.go:100–175` duplicate identical pagination clamping, validSortBy/validSortOrder whitelists, search ILIKE clause building, count query, and LIMIT/OFFSET assembly (`$n` via `string(rune('0'+argIndex)))`). Extract one shared filter/sort builder.
- **`internal/params/request/admin/admin.go:8–18`** — admin request/response DTOs duplicated across params and usecase layers with identical tags, but `admin_handler.go` parses the usecase structs directly (l154, 173), so the params DTOs are dead and validation silently diverges (`IsActive *bool` vs `bool`). Delete the duplicates or route handlers through them consistently.
- **`domain/ports/session_repository.go:13–17`** (Data Clumps) — `SortBy/SortOrder/Page/Limit` repeated as parallel fields in ports filter options, usecase requests, and params query DTOs (6 copies). The repeated `validSortBy` map literal (`contact_postgres.go:231`, `session_postgres.go:140`) is a Repeated Switch.
- **`internal/usecase/dashboard/get_dashboard.go:58`** (Primitive Obsession) — plain strings (`"pending"`, `"paid"` in `get_session_detail.go:88`) bypass `valueobject.PaymentStatus`, which already guards legal values.
- **`internal/handler/webhook_handler.go:71–91`** — handler contains business logic (signature verification, payload parsing, sent/failed state machine) and swallows repo update errors via inner `break` (l78–84, 86–91). Move orchestration into a notification usecase; at minimum surface the inner errors.
- **`internal/usecase/auth/register_user.go:89`** — `_ = uc.otpRepo.InvalidatePreviousOTPs` discards a DB failure without logging; rate-limit bookkeeping writes (`bulk_reminder.go:132`, `send_reminder.go:113`) similarly ignore errors. OTP invalidation should at least be logged.
- **`internal/handler/admin_handler.go:136–263`** (Divergent Change) — response envelope split-brain: `{success, data}` in most handlers, but auth (`auth_handler.go:64–168`) and admin (l64, 98) return usecase structs at top level with success inside the DTO, and several return only `{success: true}`. Clients must special-case per module.
- **`internal/middleware/admin_auth.go:15–57`** — `RequireAdminRole/RequireSuperAdminRole` accept `jwtSvc` but only read Locals set by `Authenticate` — unused parameter; either drop the arg or re-verify the role from a freshly parsed token as the comment implies.
- **`internal/router/router.go:6–25`** — router imports `internal/service` and holds `jwtService`/`rateLimitService` fields, exceeding the documented "router/ → handler, middleware" allowlist (they're only passed to middleware constructors). Extend the documented rule or pass prebuilt middleware handlers.
- **`internal/worker/` (empty)** (Speculative Generality) — empty package while staged migration `000030_notification_outbox.up.sql` adds outbox claim columns (`attempts, locked_by, next_attempt_at`) explicitly for worker queries; `whatsapp_operations.go:80–84` carries a disabled OTP-send block. Schema is ahead of code with no compensating path.

**Standards summary:** 17 findings — 6 hard violations, 11 judgement calls. Worst: the `userID`-into-`session_id` count bug (`internal/usecase/dashboard/get_dashboard.go:58`) — the dashboard reports wrong pending payments for every user.

## Security

Advisory review (not a pentest). Coverage: JWT (service/jwt.go, config.go, middleware/auth.go), roles (middleware/admin_auth.go, router.go, admin usecases/handler), public payments (router.go, payment usecases/handler), uploads (service/image.go), rate limiting (middleware/rate_limit.go, service/rate_limit.go), webhooks (both handlers), SQLi (all repositories), soft-delete (repositories, migrations 000008/000014/000024), secrets (config.go, .env.example, migration 000013). Positive assurances: JWT alg confusion properly blocked (HS256-pinned, `jwt.go:66–78`); no SQL injection — dynamic ORDER BY is whitelist-validated (`contact_postgres.go:232–247/267`, `session_postgres.go:140–156/173`), all filters parameterized; migration 000014 partial indexes match actual query shapes; filename sanitization blocks traversal (`image.go:384–395`). Not deeply reviewed: user password login flow, `get_status.go` internals.

### Hard violations

- **CRITICAL — Forgeable JWTs via known default signing secret** — `config/config.go:27`: `JWTSecret` falls back to `"your-secret-key-change-in-production"` with no startup validation; if `JWT_SECRET` is unset in prod every token (incl. the `super_admin` role claim) is forgeable → full admin takeover. Alg confusion is properly blocked (HS256-pinned), so the weakness is solely the default secret (CWE-798/1391).
- **CRITICAL — Any registered user can control the WhatsApp gateway** — `internal/router/router.go:183–187`: routes commented "Super admin only" (`/status`, `/qr-code`, `/config`, `/logout`) carry only `Authenticate`, not `RequireSuperAdminRole` (that middleware is applied only to the `/admins` group at l190); usecases add no backstop (`usecase/admin/whatsapp_operations.go:35–47, 97+`). Any verified user JWT can pair the business WhatsApp number or swap the gateway token (CWE-862).
- **HIGH — Admin OTP brute-forceable; delivery never implemented** — `internal/router/router.go:173–176`: admin auth routes (`/auth/initiate`, `/auth/login`, `/auth/verify-otp`) have no rate limiters (user auth routes do, l102–104); `VerifyOTPUseCase` does a plain string compare with no attempt counter (`usecase/admin/initiate_login.go:143`) — 6-digit space exhaustible within the 5-min expiry from one host; and the OTP is never actually delivered (l80–84 TODO), so the flow cannot be completed legitimately (CWE-307/640).
- **MEDIUM — WhatsApp webhook authenticates against a hardcoded literal** — `internal/handler/whatsapp_webhook.go:37–38`: secret compared against the string literal `"your-webhook-secret"` instead of `cfg.WhatsAppWebhookSecret` (which `webhook_handler.go:26` correctly uses); anyone knowing the constant passes the gate. Impact currently bounded: `handleConnectionStatus` is a no-op TODO (l54–58) (CWE-798).

### Judgement calls

- **MEDIUM — Rate limiting fails open; public payment endpoints unmetered** — `internal/middleware/rate_limit.go:31–35`: on Redis failure every limiter is bypassed (`fail-open`); `/payments/:participant_id/submit` (unauth 4MB image upload) and `/public` have no limiter at all (`router.go:110–113`) → S3-fill and enumeration spam (CWE-770/645).
- **MEDIUM — Raw internal error strings leak in 500 responses** — `internal/httperror/httperror.go:49–50`: non-domain errors returned verbatim to clients; every handler funnels here — DB driver, S3, and internal error strings reach clients (CWE-209). (Also a Standards hard violation; cross-cutting.)
- **MEDIUM — Long-lived unrevocable JWTs; stale role claims honored** — `config/config.go:28`: 7-day tokens, no revocation/denylist; admin logout only touches `last_login` (`whatsapp_operations.go:67–72`); the role claim is carried through `RefreshToken` (`service/jwt.go:103–113`) and trusted from context without DB recheck (`middleware/admin_auth.go:31–39`), so demoted/deleted admins keep access until expiry (CWE-613).
- **LOW — Public payment page discloses full bill data; expiry not enforced; public_slug dead** — the unauthenticated `/payments/:participant_id/public` endpoint returns session title, participant name, share, and every bill item for any participant UUID; the computed 7-day link expiry (`usecase/payment/get_payment_page.go:55–101`) is informational only — submission is gated only by `session.SessionDate` (`submit_payment.go:60–63`). UUIDv4 capability URLs are non-enumerable (mitigating); migration 000024's `public_slug` was built as the public handle but nothing references it (CWE-862/639).
- **INFORMATIONAL — Seed super_admin row is inert but unrotated** — `migrations/000013_seed_super_admin.up.sql:4–13`: placeholder bcrypt hash (invalid) and placeholder phone; `/admin/auth/login` returns 501, so the row is dormant; comments instruct rotation (CWE-1391).
- **LOW — Gateway webhook: no replay/timestamp protection** — `internal/handler/webhook_handler.go:29–45`: HMAC-verified, but no timestamp/nonce check — captured requests can be replayed to re-write notification statuses (CWE-294).

**Security summary:** 10 findings — 4 hard violations (2 critical, 1 high, 1 medium), 5 judgement calls + 1 informational. Worst: the default JWT secret (`config/config.go:27`) combined with the missing super-admin middleware on gateway-control routes (`router.go:183–187`) — either one alone hands the WhatsApp gateway and admin surface to any registered user if deployed as-is.
